## 2026-11-06 - Bounded Slice Windowing via Searchsorted for Harmonic Spectral Mask Evaluation
**Learning:** In spectral line residue metrics (e.g. `metrics.line_residue`), evaluating harmonic mask criteria across hundreds of mains harmonics (up to 6 kHz) by evaluating full-array comparisons `np.abs(freqs - k * fundamental) <= width` on the entire `freqs` array causes $O(K \times N)$ array allocations and linear scans (>14 million element evaluations per call for 5s of 48 kHz audio). Because `freqs` is strictly monotonic, each harmonic window spans only a narrow slice of bins (~10–80 bins). Locating the index bounds for all harmonics via `np.searchsorted` and evaluating the mask only across those localized slices reduces mask creation time by >30x (from ~28 ms to ~0.9 ms) and accelerates overall `line_residue` by 2.45x (from ~46.1 ms to ~18.8 ms) while preserving bit-exact results.
**Action:** When constructing multi-harmonic or multi-band boolean masks over monotonic frequency bins, compute index bounds with `np.searchsorted` and evaluate slice-by-slice rather than scanning the entire array for each band.

## 2026-11-06 - Prefix-Sum Vectorization and SOS Filter Caching in Frame Energy Estimation
**Learning:** In audio restoration pipelines estimating frame energies across analysis hops (e.g. `BodyEngine.frame_energies`), repeatedly invoking `signal.butter` for identical filter orders and passbands incurs substantial Python overhead designing analog filters and calculating second-order sections (SOS). In addition, computing sliding window means across thousands of analysis hops via Python list comprehension `np.array([band[i * hop: i * hop + frame].mean() ...])` causes Python slice indexing overhead and redundant work. Caching SOS coefficients with `@functools.lru_cache` and precomputing the cumulative sum of squared band energy `np.cumsum(band)` reduces arbitrary window energy calculations to vectorized $O(1)$ prefix-sum differences across all hops without looping, saving ~30 ms on 60s audio.
**Action:** When computing fixed- or variable-width moving window power or means over filtered series, cache filter designs via `@functools.lru_cache` and compute window sums using `np.cumsum` prefix-sum lookups instead of per-hop Python slices.

## 2026-11-06 - ZoomFFT Chirp Z-Transform Evaluation in Harmonic Tracking and Batched Multi-Band SOS Filtering
**Learning:** In harmonic mains hum and tonal noise tracking (such as in `DehumEngine._track`), evaluating DTFT power over fine frequency search grids by explicitly evaluating complex exponentials `x * exp(-2j * pi * k * f * t)` inside nested Python loops incurs $O(N \times F \times K)$ operations and interpreter overhead. Using `scipy.signal.ZoomFFT` (Chirp Z-transform) evaluates the exact discrete Fourier transform across arbitrary narrowband frequency intervals in $O(N \log N)$ FFT operations, achieving bit-exact numerical agreement (<1e-12 diff) while cutting tracking calculation time by >15x. In addition, when filtering baseband harmonic blocks alongside local offset side bands for prominence checking, stacking the block and its offset rotations into a single 2D array and passing it to `sosfiltfilt(..., axis=-1)` executes the filter in a single C pass rather than 5 individual filter calls per harmonic.
**Action:** When evaluating DTFT or power spectra across arbitrary narrowband frequency grids, use `scipy.signal.ZoomFFT` instead of manual exponential loops. For multi-offset or multi-component filtering with identical filter parameters, stack signals along a new axis and filter in one `sosfiltfilt` invocation.

## 2026-10-04 - Strided Window Vectorization of Running Maximum Envelopes
**Learning:** In audio envelope tracking (e.g., release-hold decay in `DeplosiveEngine`), computing a sliding running maximum over past frames via Python list comprehension `np.array([cut[max(0, i - release): i + 1].max() for i in range(len(cut))])` incurs heavy interpreter overhead and thousands of temporary array allocations per audio take. Padding the cut array on the left with `-np.inf` and creating a 2D strided view via `sliding_window_view(padded_cut, release + 1)` allows numpy's C implementation to compute `np.max(..., axis=-1)` across all frames simultaneously with zero additional copies, eliminating ~10 ms of overhead per call.
**Action:** When computing fixed-window running maximum or minimum filters on 1D series, pad with the identity element (`-np.inf` for max, `+np.inf` for min) and use `sliding_window_view` with vector reduction instead of per-step Python slices.

## 2026-10-04 - 1D Logarithmic Decomposition in Spectrotemporal Masking
**Learning:** In adaptive audio crossover routers (`RouterEngine._crossfade`), computing octave distance grids between frequency bins and time-varying cutoff boundaries $\log_2(\text{freqs} / \text{edge})$ via 2D broadcasting `freqs[:, None] / edge[None, :]` evaluates floating-point 2D division and transcendental $\log_2$ on every single grid point ($O(M \times N)$, e.g. ~10^6 elements for a 10s audio take). Decomposing the logarithm mathematically as $\log_2(\text{freqs}) - \log_2(\text{edge})$ reduces the transcendental computations to 1D vectors ($O(M + N)$), eliminating ~500x transcendental calls and accelerating the crossfade calculation by 6–8x while delivering identical output.
**Action:** When calculating 2D spectrotemporal logarithmic distance or ratios $f(x, y) = \log(x / y)$ across independent axes, decompose into $\log(x) - \log(y)$ on 1D vectors prior to 2D broadcast subtraction instead of computing 2D division inside the logarithm.

## 2026-10-04 - Strided Vectorization of YIN Lag Difference and Hoisting Harmonic Power Allocation
**Learning:** In audio pitch tracking (YIN algorithm) and low-frequency harmonic reconstruction (e.g., `BodyEngine`), computing the squared difference function $d(\tau) = \sum (frame - y_{delayed})^2$ via Python list comprehension over hundreds of lags per frame causes major interpreter overhead and redundant allocations. Creating a 2D view via `sliding_window_view` and reducing with `np.einsum('ij,ij->i', diff, diff)` accelerates the difference function evaluation by ~5x. Furthermore, harmonic share calculation in harmonic synthesis loops does not depend on the harmonic index $k$, so computing it once outside the loop across all pitch values with 2D broadcasting avoids re-evaluating slow list comprehensions in nested iterations.
**Action:** In time-domain lag or sliding difference searches like YIN, use `sliding_window_view` with `np.einsum` row-wise dot products instead of iterating over lags in Python. Hoist loop-invariant spectrum/harmonic sharing computations outside synthesis loops.

## 2026-10-04 - Prefix-Sum Vectorization for Fractional-Octave Spectrum Smoothing
**Learning:** Computing fractional-octave or moving-band smoothing across frequency bins in spectral matching engines (e.g., `ToneMatchEngine._smooth`) by evaluating boolean condition masks `(freqs >= lo) & (freqs <= hi)` inside a Python loop incurs $O(N^2)$ array allocations and linear scans. Because frequency bins from STFT/Welch power spectra are strictly monotonically increasing, the band boundaries can be located via binary search (`np.searchsorted`) in $O(N \log N)$ and slice averages evaluated in $O(1)$ with prefix sums (`np.cumsum`), dropping smoothing runtime from ~85 ms to ~0.27 ms per call (>300x faster).
**Action:** When computing windowed or fractional-octave energy averages across sorted spectrum bins, use `np.searchsorted` for boundary indices and prefix sums via `np.cumsum` to avoid quadratic boolean mask creation.

## 2026-10-03 - Complex Baseband Filtering in Dehum Engine
**Learning:** In audio restoration pipelines using demodulated complex baseband estimation (like `DehumEngine`), smoothing filters are evaluated thousands of times across harmonics and local offset bands. `signal.butter` has substantial overhead (designing analog filter, bilinear transform, pole-zero pairing to SOS), making repeated filter construction a major bottleneck. Furthermore, `sosfiltfilt` supports multidimensional arrays along an axis (`axis=-1`), allowing complex components to be filtered simultaneously in a single 2D pass instead of two separate passes for real and imaginary parts.
**Action:** When applying Butterworth/SOS filtering repeatedly with fixed (bandwidth, sample_rate) parameters, cache filter coefficients with `functools.lru_cache` and stack multi-channel/complex components along a new axis to run `sosfiltfilt` once.
